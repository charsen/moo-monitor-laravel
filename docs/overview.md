# 后端监控项目概览

`charsen/moo-monitor-laravel` 是 Laravel 后端监控采集 SDK。它收集运行时异常和慢 SQL，先写本地缓冲，再增量推送到 Moo Scaffold Cloud，供云端集中查看和处理。

## 核心能力

| 能力 | 说明 |
| --- | --- |
| 异常采集 | 接入框架异常上报链，并通过独立开关补充日志异常、HTTP 5xx、队列失败和调度失败等路径。 |
| 慢 SQL | 按耗时阈值记录查询及调用上下文，默认关闭，由 Host 按需启用。 |
| 聚合与脱敏 | 相同问题按稳定指纹聚合；请求、用户和 SQL 上下文按配置脱敏。 |
| 本地缓冲 | 默认写入 `storage/moo-monitor/`，通过游标和逐条回执管理推送进度。 |
| 环境隔离 | 同一 Host 的多环境运行可隔离缓冲、游标、部分确认记录和同步锁。 |
| Cloud 与 MCP | 提供云端推送和 MCP 命令，使用对应 Token 能力访问云端接口。 |

## 运行与职责边界

本包是无页面的采集端，不注册业务路由，也不拥有 Host 业务数据。开发工具界面由 Scaffold 提供，问题查看、告警和处置由 Cloud 提供；Host 负责配置采集范围、脱敏字段、凭据及定时运行方式。

运行时采集默认开启，慢 SQL 默认关闭。云端推送由 `moo-monitor` 配置控制；启用自动推送后仍需 Host 驱动 Laravel Scheduler。具体配置与命令见 [安装和接入说明](../README.md)。

采集和推送失败不能改变 Host 的业务响应。云端不可用时保留未确认缓冲；本地目录属于可恢复状态，不应作为普通临时日志随意删除。多环境隔离规则与逐条回执格式属于持久化契约，调整前需核对生产者与消费者。

## 已知采集边界

采集钩子注册前的启动异常、自带 `report()` 且提前短路的异常路径，以及刻意排除的 deprecation 通知，不代表都能进入云端。框架过滤与 Host 的异常处理方式也会影响结果；完整覆盖说明以 [README](../README.md) 和当前实现为准，不将 SDK 安装成功等同于所有异常均已覆盖。
